# 🏛️ OOP PRINCIPLES TO MAINTAIN (CRITICAL FOR LONGEVITY)

## 1. SINGLE RESPONSIBILITY PRINCIPLE (SRP)
- Each file has ONE job only
- Screens = UI rendering only
- Hooks = State management + business logic
- Services = API calls + data transformation
- Utils = Helper functions

## 2. OPEN/CLOSED PRINCIPLE (OCP)
- Services extend BaseService (open for extension, closed for modification)
- Validation strategies implement base interface
- Add new features by creating new files, not modifying existing ones

## 3. LISKOV SUBSTITUTION PRINCIPLE (LSP)
- Any service can be replaced with a mock service for testing
- All validation strategies work interchangeably

## 4. INTERFACE SEGREGATION PRINCIPLE (ISP)
- Small, focused interfaces (not large monolithic services)
- Each hook handles ONE specific domain (auth, activation, inventory)

## 5. DEPENDENCY INVERSION PRINCIPLE (DIP)
- Use container.js for dependency injection
- Screens depend on hooks, not on services directly
- Services depend on BaseService abstraction

## 6. DRY (DON'T REPEAT YOURSELF)
- Validation logic = one place (validationStrategies.js)
- Logging = one place (logger.js)
- HTTP requests = one place (BaseService.js)

## 7. KISS (KEEP IT SIMPLE, STUPID)
- 200 lines per screen is IDEAL
- 100-150 lines per hook is IDEAL
- 50-100 lines per service is IDEAL

## 8. YAGNI (YOU AREN'T GONNA NEED IT)
- Don't add features until needed
- Current architecture is sufficient for now
