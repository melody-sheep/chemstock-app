## 🚀 MEMBER GUIDELINES - REUSABLE COMPONENTS & ARCHITECTURE

### ⚠️ IMPORTANT: BEFORE YOU CODE, READ THIS!

This project follows strict **OOP (Object-Oriented Programming)** and **SOLID Principles**. All code must adhere to the architecture below.

---

### ✅ 1. ALWAYS USE REUSABLE COMPONENTS

**NEVER create new components when you can reuse existing ones.**

#### Component Library:

| Component | Purpose | Location |
|-----------|---------|----------|
| **Button** | All buttons (primary, outline, danger) | `src/components/common/Button.js` |
| **Input** | All form inputs with validation | `src/components/common/Input.js` |
| **Card** | All card containers | `src/components/common/Card.js` |
| **Header** | All app headers | `src/components/common/Header.js` |
| **Icon** | All SVG icons (Phosphor) | `src/components/common/Icon.js` |
| **Modal** | All bottom sheets/modals | `src/components/common/Modal.js` |
| **ScreenContainer** | All screen wrappers | `src/components/common/ScreenContainer.js` |
| **LoadingSpinner** | All loading indicators | `src/components/ui/LoadingSpinner.js` |
| **Divider** | All horizontal dividers | `src/components/ui/Divider.js` |

#### ❌ DON'T DO THIS:
```javascript
// WRONG - Creating a custom button in a screen
<TouchableOpacity style={styles.customButton}>
  <Text>Submit</Text>
</TouchableOpacity>
```

#### ✅ DO THIS:
```javascript
// CORRECT - Using reusable Button component
import Button from '../../components/common/Button';

<Button title="Submit" onPress={handleSubmit} variant="primary" />
```

---

### ✅ 2. OOP & SOLID PRINCIPLES - MANDATORY

| Principle | Rule | Example |
|-----------|------|---------|
| **SRP** | One file = One responsibility | Screen = UI only, Hook = Logic, Service = API |
| **OCP** | Extend, don't modify | Services extend BaseService |
| **LSP** | Subtypes must be substitutable | All services can be mocked |
| **ISP** | Small, focused interfaces | authService, activationService |
| **DIP** | Depend on abstractions | Use container.js for DI |
| **DRY** | Don't repeat yourself | colors.js, typography.js |
| **KISS** | Keep it simple | Screens < 200 lines |
| **YAGNI** | You ain't gonna need it | No premature code |

---

### ✅ 3. DEPENDENCY INJECTION - MANDATORY

**Always use container.js for service injection:**

```javascript
// ❌ WRONG - Direct import
import authService from '../services/authService';

// ✅ CORRECT - Use container
import container from '../container';
const authService = container.get('authService');
```

---

### ✅ 4. SCREEN ARCHITECTURE - MANDATORY

**Screens MUST follow this pattern:**

```
Screen.js
  ├── UI Only (JSX)
  ├── Uses Hooks for logic
  └── Uses Services for API
```

**Screen Structure:**
```javascript
export default function MyScreen() {
  // 1. Hooks (useAuth, useActivation, etc.)
  const { user, login } = useAuth();
  
  // 2. UI State (local state only)
  const [localState, setLocalState] = useState();
  
  // 3. Handlers (call hooks)
  const handleSubmit = () => { login(data); };
  
  // 4. Render (UI only)
  return (
    <ScreenContainer>
      <Header />
      <Input />
      <Button />
    </ScreenContainer>
  );
}
```

---

### ✅ 5. SERVICE ARCHITECTURE - MANDATORY

**All services MUST extend BaseService:**

```javascript
// ✅ CORRECT
import { BaseService } from './BaseService';

class MyService extends BaseService {
  constructor() {
    super('MyService');
  }
  
  async myMethod() {
    return this.handleRequest(async () => {
      // API call
    });
  }
}
```

---

### ✅ 6. HOOKS ARCHITECTURE - MANDATORY

**Hooks MUST implement MVVM ViewModel pattern:**

```javascript
// ✅ CORRECT
class MyViewModel {
  constructor(service) {
    this.service = service;
    this.state = {};
  }
  
  async doSomething() {
    // Logic here
  }
}

export function useMyFeature() {
  const viewModel = useRef(new MyViewModel(service));
  // Return state and methods
}
```

---

### ✅ 7. CONSTANTS - SINGLE SOURCE OF TRUTH

| Constant File | Used For |
|---------------|----------|
| `colors.js` | ALL colors in the app |
| `spacing.js` | ALL spacing values |
| `typography.js` | ALL font styles |
| `roles.js` | ALL user roles |

**NEVER hardcode colors, spacing, or fonts:**

```javascript
// ❌ WRONG
<Text style={{ color: '#FF0000', fontSize: 16 }}>

// ✅ CORRECT
import { COLORS } from '../constants/colors';
import { TYPOGRAPHY } from '../styles/typography';
<Text style={{ color: COLORS.error, fontSize: TYPOGRAPHY.fontSize.base }}>
```

---

### ✅ 8. VALIDATION - STRATEGY PATTERN

**Use validationStrategies.js for ALL validation:**

```javascript
// ❌ WRONG
if (!email || !email.includes('@')) { // Invalid }

// ✅ CORRECT
import { EmailValidationStrategy } from '../utils/validationStrategies';
const emailStrategy = new EmailValidationStrategy();
if (!emailStrategy.validate(email)) {
  // Error handling
}
```

---

### ✅ 9. LOGGING - CENTRALIZED

**Use logger.js for ALL console logs:**

```javascript
// ❌ WRONG
console.log('User logged in');

// ✅ CORRECT
import { debugLog } from '../utils/logger';
debugLog('info', 'MyComponent', 'User logged in', { userId });
```

